## 1. Executive Summary, Core Pillars & Changelist

### 🌟 Ecosystem Value Proposition & Unified Story
**Impulse Graph Engine** (`impulse-graph`) is an ultra-high-performance, zero-copy, C-ABI binary snapshot graph engine designed for sub-millisecond cold starts, sub-microsecond vector traversals, and multi-terabyte (TB+) scale graph analytics.

**The Gap in the Open-Source Ecosystem**:
Traditional open-source graph databases (e.g. Neo4j, JanusGraph) and scripting libraries (e.g. NetworkX, igraph) present a sharp trade-off:
- *Transactional Graph Databases*: High JVM/GC overhead, seconds-to-minutes dataset load times, heavy memory footprints, and complex server clustering.
- *Scripting Libraries*: Single-threaded execution, poor SIMD vectorization, lack of cloud streaming support, and weak polyglot interop.

**Impulse Graph fills this missing gap** by serving as the **Apache Arrow / Parquet equivalent for Graph Analytics**. It pairs an immutable, memory-mapped binary snapshot format (`.imps`) with a register-based Virtual Machine (`ImpulseVM`) that executes SIMD-vectorized graph algorithms directly off-heap without heap allocations or GC pauses.

---

### 🏛️ The 4 Core Architectural Pillars of Impulse Graph

1. **Pillar 1: Impulse Binary Snapshot Format (`.imps`)**
   - **Zero-Copy Memory-Mapped Storage**: Off-heap `mmap` files conforming to C-ABI Spec (`magic: 0x494D5053`, `version: 0x0009`).
   - **Hardware Vector Alignment**: Strict 128-byte alignment across all offset sections for AVX-512 vector units, GPU warp coalescing (NVIDIA GPUDirect Storage `cuFile`), and TPU vector tiles.
   - **Single-Pass S3 Cloud Streaming Write**: `SnapshotWriter` streams binary files direct to cloud object storage (Amazon S3, Google Cloud Storage) in $O(\text{chunk})$ physical RAM footprint without requiring random file seeks.

2. **Pillar 2: Impulse VM Query Engine (`ImpulseVM` & `impOps`)**
   - **`ImpulseVM` Execution Engine**: The high-performance Virtual Machine execution runtime available as a direct-threaded C++ kernel (`impulse_vm.cpp`) and a HotSpot C2 `MethodHandle` JIT-inlined Java 25 FFM interpreter (`ImpulseVmInterpreter.java`).
   - **`impOps` Instruction Set Architecture (ISA)**: Register-based opcode specification (opcodes `0x01`..`0x6A`) defining instruction contracts for graph traversals (`OP_CSR_WALK`, `OP_CSC_WALK`), GraphBLAS operations (`OP_MXV`, `OP_VXM`), connected components (`OP_CC_AFFOREST`), and SIMD bitset filtering (`OP_COLLECT_BITSET`).
   - **ImpVM Tooling**: Human-readable text assembly parsing (`.imp` / `.imps`), disassembly (`impulse disassemble`), and CLI bytecode runner (`impulse run`).

3. **Pillar 3: Polyglot Client Libraries & Native FFI Bindings**
   - **Unified Polyglot API**: Native C-ABI C header (`impulse_graph.h`), Java 25 Vector API & FFM (`impulse-core`), Rust crate (`impulse-graph`), Python PyTorch `torch.sparse_csr_tensor` zero-copy `mmap` tensors, Go, Node.js N-API, and C#/.NET 9.
   - **Fluent Query Builders**: Ergonomic, strongly-typed fluent APIs in every host language mapping directly into `impOps` bytecode execution plans.

4. **Pillar 4: Empirical Benchmark-Driven Engineering**
   - **Zero Estimated Benchmark Claims**: All published metrics, execution latencies, throughput (MTEPS/QPS), and JVM/C++ comparisons are derived exclusively from actual empirical runtime execution logs on physical hardware.
   - **Standard Macro Benchmarks**: Standardized GAPBS (Graph500) benchmarks (`twitter-2010` 1.47B edges), ReBAC Zanzibar fine-grained authz checks, and power grid stability SIMD island detection.

## 3. Architecture & API Stability Matrix

### 3.1 Core Architecture Focus: Read-Only (RO) Zero-Copy Queries
- **Decision**: Deprecate dynamic R/W delta overlays in core query kernels to focus 100% of execution engine optimizations on **ultra-high performance Read-Only (RO) queries over immutable zero-copy `.imps` snapshots**.
- **Rationale**:
  - Live data ingestion and real-time updates are handled out-of-band by streaming compilers (`impulse-compile`, `impulse-platform`) that produce updated `.imps` snapshots via single-pass S3 streaming writes.
  - Eliminating in-memory mutation locks and delta overlay merging restores pure lock-free, zero-allocation vector performance across AVX-512 and GPU warp execution paths.

### 3.2 SemVer API & ABI Stability Matrix ( -> v1.0.0)

| Layer / API Boundary | Stability Status | Target Status for v1.0.0 | Description & Policy |
| :--- | :--- | :--- | :--- |
| **C-ABI & Binary Format (`.imps`)** | 🟢 **Near-Stable (95% Freeze)** | 🔒 **100% Frozen & Backward-Compatible** | C-ABI header layout, 128-byte alignment, and Section 2 string pool layout are frozen. Minor additive flags allowed during 0.9.x patch releases. |
| **`impOps` VM Bytecode Spec** | 🟢 **Stable Protocol (90% Freeze)** | 🔒 **100% Stable Bytecode Format** | Opcodes `0x01`..`0x6A` are locked. Additional domain opcodes may be added cleanly. |
| **Java 25 FFM API** (`impulse-core`) | 🟡 **In Flux / Evolving** | 🔒 **Frozen Public Java API** | FFM layout and `ImpulseVmInterpreter` API will be refined based on public 0.9.x feedback. |
| **C++ Native Core API** | 🟡 **In Flux / Evolving** | 🔒 **Frozen C++ Header API** | `impulse_graph.h` and C++ fluent query builder will be finalized during 0.9.x. |
| **Python / Rust / .NET Bindings** | 🟠 **Beta / Evolving** | 🔒 **Frozen Polyglot Bindings** | Bindings will track C++ / Java API refinements. |

2. **Community Feedback & 0.9.x Patch Iterations**: Solicit real-world feedback, run macro benchmarks, and release patch updates (`v0.9.1`, `v0.9.2`, etc.) to polish Java and C++ public APIs.
